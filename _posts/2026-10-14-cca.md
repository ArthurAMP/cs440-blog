## Key Idea

This paper's core objective is to evaluate different INT signals on their worth for congestion control algorithms. To do this paper presents R+, an algorithm to find lCCAs, which are CCAs generated to maximize provided utility functions given a fixed set of network scenarios and signals. From there, they used a different simulator to evaluate the CCA on ns-3, a different simulator, and recorded its score. Then, by changing the signals given as input to R+, they could evaluate which set of signals led to better results according to the same utility function. The conclusion reached was that no set of signals performed significantly better on average, although there were some small gaps in some cases (especially if using an extreme utility function). This paper also suggests although there is no set of signals that performs generally better, some signals are better suited for certain kinds of demands. As an example, link does best at high loads, but queue does best at lower loads.  

## Critique

This is a very instructive paper; it was a great read and I learned a lot about CCAs from it. 

I like how they were honest about the paper's limitations, with statements such as "The design space our work addressed is infinite, so this paper is not intended to make
definitive declarations about in-network signals." However, even then I believe the limitations were understated. This sentence in specific was a little jarring to me: "Closer inspection of the distribution of score differences revealed few significant differences between the CCAs with INT vs. E2E signals (especially as the error for all signals, but notably E2E, increased). Thus, our basic result holds for these multi-hop topologies." This is almost tautological; of course it will be harder to find siginificant differences as the error increase. Using that in the same two sentences you claim your basic result holds for those cases is a bit surprising. 

Additionally, I was surprised there was no section going over the parameters for learning CCAs. On the presentation video, McClure (the presenter) briefly mentions the parameters are reasonable, but nothing else. 

## Connections

Changing optimization approaches could lead to interesting results. The first thing that came to mind was framing it as an optimization problem that MetaOpt can work with, similar to the [Raha paper I posted about a few weeks ago](/cs440-blog/2026/10/04/raha/). One could construct adversarial network configurations for each signal to attempt to conform the best it can. This way, we could find edge cases that could be missed by random sampling.
